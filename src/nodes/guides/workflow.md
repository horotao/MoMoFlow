# Image 工作流

Image 可先连线再运行。运行前检查节点的提示词、参考图、锁定状态和所选模型。执行器按依赖顺序准备输入，根据输入和输出记录判断是否可复用上游结果。

任务按节点记录进度，可取消或手动重试。结果随工作流保存，刷新后可继续选择已有图片；进行中的任务状态只在当前会话内维护。调度与重试见 [workflowExecution.ts](../workflowExecution.ts)，界面接入见 [useWorkflowExecution.ts](../../components/useWorkflowExecution.ts)。

Image 多模型运行会在原节点生成第一个模型的结果，其余模型各自生成到一个新节点。原节点保留模型选择、历史和已有连线，本次选区运行的下游等待原节点的结果。新节点和它们的入线可一次撤销。

多选工具栏的「运行所选节点」启动选中的未锁定 Image 和 Text，沿用各节点的模型、提示词和生成数量。导入图片只作为已有参考图参与，只有静态素材或锁定节点时运行按钮禁用。独立节点可并行运行，选区内有连线时下游等待本次上游结果。缺少输入的节点不提交模型请求，未选中的上游仅提供已有输入。一次最多运行 50 个生成节点，同一次运行结束前重复点击不会重复提交已安排的节点。

选中至少两个未编组节点后可编组。框围绕成员原有边界建立，拖动框内留白或标题可整体移动。含锁定成员的群组无法整体移动。悬停群组显示工具栏，选中后保持显示。工具栏可更改群组颜色、解组、下载成员当前结果、对齐和自动整理组内节点、运行可生成的成员。解组保留节点位置和连线。群组、标题和颜色随项目保存；编组、解组和整体拖动均可撤销。

群组标题使用纯文字，新建群组依次使用空闲的 `Field`、`Field 1`、`Field 2` 等名称。双击标题可重命名，已保存的名称会保留。画布显示的缩放比例降到 14% 或以下时隐藏标题，正在编辑的名称可继续输入。群组工具栏和多选工具栏使用相同的淡入、淡出和短距离位移，并遵循减少动态效果设置。

拖动节点并松手时，节点中心落在群组框内即加入该组。已有成员只要仍与旧框有面积相交，就留在原组，除非中心已经进入另一个组并离开原组。越出框线的一侧会扩到节点边缘外 64 个画布像素。节点完全离开后，原框保留尺寸，空组也保留。直接跨组时，松手位置若仍与旧框相交，旧框和目标框会分别在需要的一侧扩展。拖动、归属和框尺寸合为一次撤销。

光标移到群组框的四边或四角时可直接拖动边框。四边分别调整宽或高，四角同时调整两者。画布只显示原边框，成员坐标、大小和连线保持原样，成员可超出框线。每次缩放可一次撤销，框的位置和尺寸会随项目保存。

## 旧项目迁移

[迁移逻辑](../../persistence/legacyImageMigration.ts)将旧 GPT Image、Seedream 和 Nano Banana 节点转成新版 Image，保留模型设置、结果、历史、位置和锁定。旧 Prompt 的可解析文本进入下游 Image 的提示词；独立的非空 Prompt 变为可编辑提示词的 Image。Prompt 的变量按迁移时的值展开。

旧 File 的图片进入新版 Image 的历史，保留当前图片和可用的参考图连线。新版 Image 每条连线输出当前选中的一张图。旧项目中的 Mask、标注连线、非图片媒体和无法映射的节点或端口保存在原始快照中。

Image 节点保存顶部中心坐标。旧坐标按原先 384 × 384 方框的顶部中心转换，重新打开时继续使用该锚点。

第一次保存迁移后的项目时，[存储层](../../persistence/workflowStorage.ts)把迁移前的完整工作流和本地素材键登记到本项目 IndexedDB 的 `workflows/pre-image-migration`。备份和当前画布在同一事务中写入，后续自动保存和素材清理继续保护快照引用的 Blob。重新打开项目沿用已保存的新版工作流。

## Text 生成

新版 Text 带 `textComposer` 标记，迁移时保留节点、结果、格式、模型选择、坐标和兼容连接，不再当作旧 Prompt 转成 Image。无标记的旧 Prompt 继续沿用上述迁移规则。

Text 的发送按钮直接运行 [文本请求](../textGeneration.ts)，经 [后端文本路由](../../../server/text.ts) 流式返回模型文本。GPT 模型走 OpenAI Responses API，DeepSeek V4.1 Flash 使用 APIMart 的 `/v1/chat/completions`，模型 ID 为 `deepseek-v4.1-flash`。Text 输入优先使用上游当前选中的已完成结果；上游尚未生成时直接使用其手写提示词，与本节点提示词以空行合并。点击下游只请求下游，不会先生成上游或增加上游历史；图片输入按 `image-0` 至 `image-15` 排序，使用上游当前选中的图片。上游文字和结果都为空时提示补充内容，避免把空输入提交给模型。至少需要本节点提示词或非空上游文本。预计费用使用相同的文本解析规则；切换历史结果后下一次下游请求同步使用当前项。

API 设置按模型渠道读取 OpenAI 或 APIMart 的 Key 与 Base URL。本地默认 Key 分别来自 `OPENAI_API_KEY` 和 `APIMART_API_KEY`，线上使用用户填写的凭据。模型、格式和提示词保存在 `textComposer`，完成结果保存在 `text`，模型、响应 ID 和时间保存在 `textGeneration`。运行期间增量只在内存。OpenAI 收到 `response.completed` 后保存；APIMart 收到 `finish_reason: "stop"` 后，在流结束时保存正文和可用用量。断流、失败、超时和取消均保留上次成功结果，不自动重试。关闭节点、切换项目、刷新或主动停止会取消接收，已提交的 API 请求仍可能计费。

当前每次可生成 1–20 份结果，直接选择一个模型。每份分别发出一次模型请求，每个 Text 节点最多并发三份，其余等待。启动时一次捕获提示词、上游文本、参考图片字节与当前模型的 API 配置，整批使用相同输入；运行中修改参数只影响下一批。自动选择和多模型仍在提交前提示不支持。旧占位 GPT-4.1、GPT-4o、o4-mini 分别映射到 GPT-6.2 Sol、GPT-6.1 Terra、GPT-6 Luna。新建 Text 默认 GPT-6.2 Sol。

每份成功后立即向 `textHistory` 保存文本、原始本节点提示词、模型、思考强度、网络搜索开关、来源引用、实际用量、计费快照、Response ID 与时间。整批按提交顺序排列，响应乱序完成也不会互相覆盖或重复。第二份结果起显示 T 历史缩略图；切换时同步 `activeTextResultId`、`text`、`textGeneration` 和提示词／模型／思考强度／搜索开关，所以下游使用当前历史项及其来源 URL。格式与数量保持用户当前选择。旧版单份 `text` 在首次追加时保留为第一条记录；刷新、撤销／重做和项目保存均保留完整历史及选择。

默认查看首个未完成项，整批结束后选中最后一份成功结果；用户主动选择历史或批内某份时保留该选择，不被其他完成项抢走。单份失败不提交其部分文本、不自动重试，其余继续，结束后汇总错误。运行项的发送按钮停止整批：中断正在接收的请求，不再启动等待项，已完成结果保留。删除节点、切换项目或刷新同样取消本批，等待项不保存或自动续跑。

每份 Text 的实际用量和可用的费用快照保存在该条 `textHistory` 结果的 `usage`／`billing`。DeepSeek 按 APIMart 的 Gold 基准价估算整批费用，实际账户费率以服务商账单为准，有 token 用量时随结果保存。切换历史直接读取该条已有的金额。批量请求每份独立计费与保存，预计费用则是整批；失败、取消及未获得完成确认的调用仍不追加结果，不能据此断言未计费。


## Image 使用 Text Prompt

Image 的 `prompt` 输入读取 Text 当前选中的已完成结果（含引用 URL），尚未生成时读取手写提示词，完全替代 Image 自己的草稿。连接未提供非空文字时阻止运行；断开后使用保留的本地草稿。所有 Image 生成模型共用这条规则。

运行 Image 只读取 Text 的输出，不运行 Text，也不遍历 Text 的上游图片或文本依赖。Text 锁定仍可提供现有文字；流式生成中仅使用上次已完成结果或手写提示词。Image 自己的参考图仍按既有依赖流程处理。Prompt 连线和本地草稿一起保存，混合旧项目迁移时保留新版 Text 到 Image 的连接。
