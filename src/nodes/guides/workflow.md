# Image 工作流

Image 可先连线再运行。运行前检查节点的提示词、参考图、锁定状态和所选模型。执行器按依赖顺序准备输入，根据输入和输出记录判断是否可复用上游结果。

任务按节点记录进度，可取消或手动重试。结果随工作流保存，刷新后可继续选择已有图片；进行中的任务状态只在当前会话内维护。调度与重试见 [workflowExecution.ts](../workflowExecution.ts)，界面接入见 [useWorkflowExecution.ts](../../components/useWorkflowExecution.ts)。

## 旧项目迁移

[迁移逻辑](../../persistence/legacyImageMigration.ts)将旧 GPT Image、Seedream 和 Nano Banana 节点转成新版 Image，保留模型设置、结果、历史、位置和锁定。旧 Prompt 的可解析文本进入下游 Image 的提示词；独立的非空 Prompt 变为可编辑提示词的 Image。Prompt 的变量按迁移时的值展开。

旧 File 的图片进入新版 Image 的历史，保留当前图片和可用的参考图连线。新版 Image 每条连线输出当前选中的一张图。旧项目中的 Mask、标注连线、非图片媒体和无法映射的节点或端口保存在原始快照中。

Image 节点保存顶部中心坐标。旧坐标按原先 384 × 384 方框的顶部中心转换，重新打开时继续使用该锚点。

第一次保存迁移后的项目时，[存储层](../../persistence/workflowStorage.ts)把迁移前的完整工作流和本地素材键登记到本项目 IndexedDB 的 `workflows/pre-image-migration`。备份和当前画布在同一事务中写入，后续自动保存和素材清理继续保护快照引用的 Blob。重新打开项目沿用已保存的新版工作流。

## Text 生成

新版 Text 带 `textComposer` 标记，迁移时保留节点、结果、格式、模型选择、坐标和兼容连接，不再当作旧 Prompt 转成 Image。无标记的旧 Prompt 继续沿用上述迁移规则。

Text 的发送按钮直接运行 [文本请求](../textGeneration.ts)，通过 [后端 Responses API](../../../server/text.ts) 流式返回模型文本。它与图像任务执行器、任务队列独立。Text 输入优先使用上游当前选中的已完成结果；上游尚未生成时直接使用其手写提示词，与本节点提示词以空行合并。点击下游只请求下游，不会先生成上游或增加上游历史；图片输入按 `image-0` 至 `image-15` 排序，使用上游当前选中的图片。上游文字和结果都为空时提示补充内容，避免把空输入提交给模型。至少需要本节点提示词或非空上游文本。预计费用使用相同的文本解析规则；切换历史结果后下一次下游请求同步使用当前项。

本地复用 `OPENAI_API_KEY`，也支持 API 设置中的 OpenAI Key 与 Base URL；线上沿用 BYOK，不加载服务器默认 Key。模型、格式和提示词保存在 `textComposer`，完成结果保存在 `text`，模型、Response ID 和时间保存在 `textGeneration`。运行期间增量只在内存，不写入撤销或保存记录。只有收到 `response.completed` 才保存；断流、失败、超时和取消均保留上次成功结果，不自动重试。关闭节点、切换项目、刷新或主动停止会取消接收，已提交的 API 请求仍可能计费。

当前每次可生成 1–20 份结果，直接选择一个模型。每份分别调用一次 Responses API，每个 Text 节点最多并发三份，其余等待；不使用模型接口的 `n` 参数。启动时一次捕获提示词、上游文本、参考图片字节与现有 OpenAI 配置，整批使用相同输入；运行中修改参数只影响下一批。自动选择和多模型仍在提交前提示不支持。旧占位 GPT-4.1、GPT-4o、o4-mini 分别映射到 GPT-6.2 Sol、GPT-6.1 Terra、GPT-6 Luna。新建 Text 默认 GPT-6.2 Sol。

每份成功后立即向 `textHistory` 保存文本、原始本节点提示词、模型、思考强度、网络搜索开关、来源引用、实际用量、计费快照、Response ID 与时间。整批按提交顺序排列，响应乱序完成也不会互相覆盖或重复。第二份结果起显示 T 历史缩略图；切换时同步 `activeTextResultId`、`text`、`textGeneration` 和提示词／模型／思考强度／搜索开关，所以下游使用当前历史项及其来源 URL。格式与数量保持用户当前选择。旧版单份 `text` 在首次追加时保留为第一条记录；刷新、撤销／重做和项目保存均保留完整历史及选择。

默认查看首个未完成项，整批结束后选中最后一份成功结果；用户主动选择历史或批内某份时保留该选择，不被其他完成项抢走。单份失败不提交其部分文本、不自动重试，其余继续，结束后汇总错误。运行项的发送按钮停止整批：中断正在接收的请求，不再启动等待项，已完成结果保留。删除节点、切换项目或刷新同样取消本批，等待项不保存或自动续跑。

每份 Text 的实际用量和费用快照保存在该条 `textHistory` 结果的 `usage`／`billing`。切换历史直接读取该条金额，不按当前模型、数量、参数或新价格重新计算。批量请求每份独立计费与保存，预计费用则是整批；失败、取消及未获得完成确认的调用仍不追加结果，不能据此断言未计费。


## Image 使用 Text Prompt

Image 的 `prompt` 输入读取 Text 当前选中的已完成结果（含引用 URL），尚未生成时读取手写提示词，完全替代 Image 自己的草稿。连接未提供非空文字时阻止运行；断开后使用保留的本地草稿。GPT Image 2.6、Seedream 5.5 与 Nano Banana 2.1 共用这条规则。

运行 Image 只读取 Text 的输出，不运行 Text，也不遍历 Text 的上游图片或文本依赖。Text 锁定仍可提供现有文字；流式生成中仅使用上次已完成结果或手写提示词。Image 自己的参考图仍按既有依赖流程处理。Prompt 连线和本地草稿一起保存，混合旧项目迁移时保留新版 Text 到 Image 的连接。
