# Image 生成动效、缩略图与缩放验收

2026-11-22，本地实际主画布 `http://localhost:5173/`，独立浏览器存储 `image-prompt-2026-11-22`，复制前轮真实生图项目建立「Image 动效与缩略图验收」。原始真实生图与编辑项目未改动。本次未提交、推送或部署。

## Flora 对照

在 Flora 既有验证 Image 上实际运行一次 Nano Banana 2.1，观察生成至完成，历史从两项增加至三项。主图与待完成缩略图均有横向填充；运行曲线为 `cubic-bezier(.33, 1, .68, 1)`，本次模型展示约 40 秒、填充时间线 80 秒。历史默认 32px、重叠 12px，展开后当前项 40px，其余 32px，卡片间距 2px；位置与尺寸投影为 250ms `cubic-bezier(.4, 0, .2, 1)`。对照视图为约 125% 画布缩放。`flora-running.jpg` 与 `flora-running.json` 为运行中截图和渲染 DOM 的动画信息。

## 发现与修复

修复前，本地实际运行显示四个历史项：两张旧图及两个没有任何子内容的黑色待完成项。已让 Image 历史项复用 `ImagePromptGeneration` 的纯填充模式，与主图共用任务起始时间和曲线；缩略图沿其 12px 圆角裁切。等待项保持零进度，选中等待项时主图也保持零进度，完成后替换为图片。

## 浏览器自动化与事件模拟

- 本地以两个延迟响应控制排队、运行和完成状态，拦截 `/api/sunburst` 返回前轮真实生成的蓝茶壶作为图片夹具，本轮本地没有调用付费图片或文本 API。图片内容和文件名不用于验证模型质量。修改源码后 Vite 重载清空了首轮受控请求；正式修复验证重新安装拦截并运行两项。
- 运行项主图和缩略图的填充矩阵差约 0.00005，排队项为 `scaleX(0)`。查看旧历史时主图停止扫光，两张待完成缩略图继续显示。选回待完成项恢复主图生成状态。
- 25%、50%、100%、150%、200% 下，历史卡片的归一化尺寸均为 32px，展开当前项 40px；两类参考卡片展开后媒体区为 32px、静止时 40px。展开／收起连续反向操作后没有残留 transform 或临时裁切；展开起始帧的历史卡片位置差为零。全部测量保存在 `verification.json`。
- T 和图片参考卡片展开时没有超出节点右边界，移除按钮中心命中卡片子元素。200% 时一次合成悬停被实际鼠标所在的图片卡片覆盖；随后使用原生浏览器悬停工具复验 T 卡片，展开正常、媒体区屏幕宽 64px、移除按钮可命中。
- Home／End 切换历史正常，画布视口不变。锁定后仍可展开 T 卡片，移除按钮不渲染，运行禁用；解锁恢复。开启小地图正常。通过实际 DOM 鼠标事件拖动图片节点，节点移动 30 × 15px、画布视口不变；画布撤销恢复，节点 DOM 平移为 `(760, 180)`，保存的顶部中心坐标为 `(952, 180)`。这里属于浏览器事件模拟，不是人工手势实测。
- 逐帧观察两次受控完成，历史始终四项，由 2 张图片／2 项进度变为 4 张图片／0 项进度，无重复项。最终图片全部加载为 1024 × 1024，主图进度层移除，原有两条连接保留。
- 减少动态效果下，扫光为 `none`，主图与缩略图填充无运行中的动画，历史悬停无位置投影动画。
- 最后刷新实际主画布，四份结果、两条连接、撤销后位置与 80% 视口均恢复，当前图片正常加载；刷新后的数据记录见 `verification.json` 中的 `reload`。
