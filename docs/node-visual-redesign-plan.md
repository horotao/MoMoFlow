# MoMoFlow 节点视觉与参数交互改版计划

更新日期：2026 年 11 月 4 日。状态：阶段 0～6 已完成；全改动复审及修复记录见文末。详见 [阶段 0 核对结果](node-visual-redesign-phase-0.md) 和下方阶段交付记录。

本次改版以 Figma 中的节点原型、连线展示及参数侧边栏为依据，统一节点外观与参数操作方式。核心变化是：名称放到节点左上方，图片和模型节点以内容预览为主体，左右端点改为图标，连线准确接入端点；常用图像工具通过顶部工具栏调参，复杂节点通过右侧面板调参。

实施顺序为：设计规格核对 → 公共结构与示范工作流 → 全局端点和连线 → 图片及模型节点 → 八类工具栏 → 高级参数侧边栏 → 全节点验收。每阶段形成可以实际操作、单独检查的成果，再进入下一阶段。当前已完成阶段 0～6，收尾与验收记录见阶段 6 交付记录。

### 已确定的产品方向

- 画布节点采用 Figma 标注的两倍尺寸：图片主体宽 400px、提示词卡片宽 452px、标题 16px、端点直径 30px、端点图标 16px。节点、标题、端点和连线随画布缩放；右侧面板不翻倍。
- 顶部参数栏采用两倍稿面尺寸（高 50px），保持屏幕上的固定大小，跟随节点定位；单击选中即显示，关闭后恢复标题。八类业务控件已在阶段 4 完成迁移。
- 标题采用“中文名称＋英文类型”，自定义名称和品牌名保留。文字连线使用 `#5F5F5F`，图片和蒙版连线统一使用浅蓝色 `#80B9F1`；两倍换算后的线宽为 3px。
- 节点名称位于左上方。普通内容节点按原型采用卡片外标题，保留自定义名称和重命名入口；路由等紧凑节点按其专门原型适配。
- 左侧输入、右侧输出使用图标端点，连线连接到图标端点的实际锚点。图标、提示文字和颜色共同表达类型。
- 绘图、模糊、调整尺寸、裁剪、混合、蒙版扩张／收缩、蒙版提取、对比，使用顶部参数工具栏，替代节点底部的参数区。
- 色彩校正、图像描述、色阶及图像生成模型不设置顶部参数工具栏，参数集中到右侧面板。
- 图片、模型和图像处理节点以预览内容为主体，下载、尺寸、结果切换及运行反馈按职责安排在预览浮层或操作区。

### 节点迁移分类

| 类别 | 节点 | 参数与交互归属 |
| --- | --- | --- |
| 文本与素材 | 提示词、文件／图片、文本迭代、图片迭代 | 保留编辑、导入与集合管理，迁移公共外观和端点 |
| 图像生成 | GPT Image 2.5、Ideogram 4.5、Nano Banana | 节点展示结果和运行状态，右侧面板编辑参数 |
| 顶部工具栏 | 绘图、模糊、调整尺寸、裁剪、混合、蒙版扩张／收缩、蒙版提取、对比 | 常用参数在顶部工具栏，完整参数通过栏内弹层承接 |
| 高级侧边栏 | 色彩校正、图像描述、色阶 | 节点保留预览或输出内容，右侧面板承接参数 |
| 其他现有节点 | 路由、参数选项、预览、反相、旋转与翻转、调色板、合成器、坐标记录 | 纳入公共样式和端点兼容检查；本轮未明确的专属布局先沿用现有功能入口 |

“图片节点”首先覆盖文件节点的图片状态，并同步覆盖模型结果和处理结果的图片预览。文件节点已有的视频、音频、3D、混合文件集合仍需保持可用。合成器的独立图层编辑器不在此次重做范围内。

## 三 分阶段实施

### 阶段 0 核对设计规格与功能差异

目标：明确可以直接实现的设计与需要补齐的交互细节，建立后续比对基准。

工作内容：

1. 提取标题、卡片、端点、连线、工具栏、侧边栏的尺寸、字体、间距、圆角、边框和颜色。核对原型是否经过缩放，避免将展示中的 6／8 像素文字直接作为应用字号，也不凭经验统一放大。
2. 固定一组代表场景：文本连接模型、图片连接模型、双输入处理、图片与蒙版双输出、Router、多图输入和已暴露参数输入。
3. 补齐未在所选画面中明确的状态：悬停、选中、多选、锁定、空内容、运行中、失败、长标题、窄窗口和浅色主题。
4. 记录顶部工具栏的打开、关闭、重开方式，标题与工具栏的避让关系，以及缩放规则。用户已确认单击选中即显示、关闭后恢复标题、保持屏幕固定大小；重开与多选的补充提案见阶段 0。
5. 对照真实功能逐项登记原型差异，见下文“实施前需明确的细节”。

交付物：设计规格表、各节点参数归属清单、固定截图场景和待定项处理记录。

核对成果已整理至 [阶段 0 核对结果](node-visual-redesign-phase-0.md)，包含八类参数栏的准确组件入口、颜色和尺寸，以及现有功能差异。用户查看 1:1 与约 2 倍尺寸对照后，已选择两倍尺寸。

完成条件：每个待迁移节点都能说明标题、预览、端点和参数放在哪里；影响模型能力或数据格式的差异有明确处理方式。

### 阶段 1 公共结构与示范工作流

目标：先做出一条可以使用的新样式工作流，验证整体比例和结构。

工作内容：

1. 建立公共节点结构，分开处理外部标题、内容卡片、预览浮层和左右端口区域。允许文本卡片、图片卡片和紧凑路由保留各自布局。
2. 建立统一图标端点组件的初版，明确图标尺寸、底座、提示文字、连接状态、禁用状态与鼠标命中区。
3. 选取提示词、文件图片状态和一个图像模型作为示范，组成“文本／图片 → 模型”工作流。使用现有结果或模拟结果验证显示。
4. 核对拖动区域、重命名、菜单、选中边界、图片比例变化与端点位置；保留原始节点坐标，不自动重新排列用户画布。
5. 新旧样式过渡限定在已迁移节点内，不将实现阶段或视觉版本写入工作流数据。

主要入口：`base-node.tsx`、`TextNode.tsx`、`FileNode.tsx`、选定模型节点及相关样式。可新增公共标题、端点、预览组件，具体命名在实施时确定。

完成条件：示范工作流可以创建、拖动、连接、改名、撤销和恢复；标题与图片比例符合设计，端点没有脱离连线。

### 阶段 2 统一图标端点与连线

目标：把影响整个画布的端点和连线作为一个完整阶段处理。

工作内容：

1. 为全部节点建立端口显示映射，覆盖文字、图片、蒙版、文件和现有其他媒体类型；同类型多个端口通过提示区分“前景／背景”“输入 1／输入 2”等用途。
2. 统一正式连线与拖线预览的颜色、粗细和曲线规则。文字线为 `#5F5F5F`，图片和蒙版线均为 `#80B9F1`；应用线宽为 3px。其他媒体沿用现有类型区分，曲率先保留现值。
3. 以 React Flow 的真实 Handle 作为连接基础。图标、可见底座、命中区和连线锚点协同定位，不能只把装饰图标移到节点外。
4. 保留所有已有 Handle ID，包括没有显式 ID 的文本输出；动态图片输入、变量输入、暴露参数及 Router 不改变连接标识或校验规则。
5. 端口数量、预览高度或布局变化时刷新端点测量；同步拖线创建节点所用的端口偏移，消除散落的旧布局常量。
6. 区分“添加”按钮和数据端口。加号只负责添加支持的输入，不作为可被连线连接的数据 Handle。
7. 处理连线选中和删除的命中区，以及线与端点的图层关系；扩大点击区域时保证视觉上的线头仍准确贴合底座。

主要入口：`App.tsx`、`ConnectionLine.tsx`、`src/edges/curve.ts`、`src/edges/index.ts`、`connectionRecommendations.ts`、`connectionRules.ts`、`router.ts`、`fileCollection.ts`、各节点端口。

完成条件：正向拖线、反向拖线、替换已连接输入、拖至空白创建节点、动态增减输入均正常。正式线和预览线类型颜色一致；旧工作流中多端口、Router、图片与蒙版连接均能恢复。

### 阶段 3 完成图片与模型节点改版

目标：将示范中的结构推广到完整的素材和模型状态。

工作内容：

## 五 实现约束与风险处理

### 数据和执行兼容

本轮默认保留节点类型、节点 ID、端口 ID、参数字段、素材 ID、结果引用和已有位置。视觉用的状态不进入执行指纹；打开工具栏、切换侧栏、选中节点或重排端点不会使已有结果失效。

若节点尺寸发生变化，应验证旧工作流中保存的宽高不会撑出空白或裁掉端点。确需转换布局字段时，应针对旧尺寸单独设计兼容处理，保持节点坐标、自定义名称、业务数据和连线不变。

图片、蒙版、透明抠图的含义继续由已有输出和素材信息决定。尤其保留 Painter 与 Masks Extractor 的双输出、Compare 的对应透传、Router 的上游追踪和蒙版恢复语义，不能用端点颜色代替这些信息。

### 参数状态与事件

工具栏和侧栏共用同一份参数来源。控件迁移时保留“临时草稿 → 提交 → 生成正式输出”的过程；面板切换、失焦、Escape、撤销或卸载必须处理未完成手势。临时预览不能被当作可下载或可供模型执行的正式结果。

连线、节点拖动、图片内绘制和工具栏滑杆各自拥有明确命中区域。弹层不会被节点边界裁切；滚动面板不会缩放画布；键盘操作既保留控件编辑能力，也保留已有撤销和画布快捷键。

### 视觉资源与组件复用

复用项目现有 React、CSS、共享选择器和图标组件。普通图标沿用现有 Hugeicons Stroke Rounded；端点和模型品牌图标以 Figma 实际资产为依据，仅在项目中存在完全一致图标时直接复用。

实施时下载所需静态资产并使用本地引用，不把 Figma 临时资源 URL 写入运行时代码；真实图片、直方图、提示词和模型结果继续由数据驱动。

不直接将大块 Figma 导出定位代码覆盖现有节点。优先增加小型公共组件，并在迁移完成后清理旧结构；避免把模型服务、执行引擎或持久化重构混入视觉阶段。

## 六 验收方式

### 每阶段共同检查

- 视觉：对照同一 Figma 场景与明确缩放，检查标题、卡片、端点、线头、工具栏、面板；覆盖长标题、空态、选中、锁定和错误状态。
- 画布：节点拖动和坐标更新、框选、多选、缩放、连接与删除、撤销重做、复制粘贴、刷新恢复。主画布当前没有小地图；仍包含小地图的独立测试页继续检查。
- 输入：数值和滑杆、下拉框、焦点、Escape、键盘操作、中文输入法。文本编辑相关阶段补验 Tab 建议、粘贴、撤销与内联变量。
- 输出：参数变更后的预览、下载和下游实际读取一致；保留原图分辨率、透明通道和蒙版含义。
- 性能：多节点和多端口场景的拖动、缩放与连线保持流畅；打开面板不新增重复 Worker，频繁拖动不会积累失效图片资源。
