# 结果图片阻挡节点拖动修复

2026-11-21，在独立站点存储的实际主画布验证，使用临时 SVG 结果素材，不调用模型。原测试画布在验证结束后恢复，临时项目通过应用的可恢复删除接口移出列表。

修复前：结果 `<img>` 默认可拖出；主画布 dragHandle 仅包含标题与工具栏。62% 缩放下通过浏览器 CDP 原生鼠标按下、移动、释放，触发 1 次 `dragstart`，节点仍为 `(240, 200)`。

修复后：主画布允许从 `.image-node-result` 拖动，并阻止结果层及历史缩略图的原生拖出。使用相同鼠标路径，`dragstart` 为 0，节点到达 `(278.71, 225.806)`，原有连线保持。鼠标路径首段用于越过拖动阈值，其后有效位移为 24×16px，除以 0.62 与节点双轴位移一致。

浏览器自动化使用原生鼠标与键盘事件，另验证：⌘Z 恢复 `(240, 200)`；切换到第二张历史图并在淡入淡出期间拖动正常，两层图片及缩略图均禁止原生拖出；锁定后相同鼠标路径不移动节点，且原生 `dragstart` 仍为 0。

`npm run check` 全部通过。未进行人工鼠标实测、真实模型调用或生产验证。

`main-canvas.png` 为另一个独立浏览器存储中的实际主画布归档，复用相同的临时素材和修复后坐标。

提交拆分时将规则收拢到独立的 `src/components/canvasImageDrag.ts`：节点映射保留锁定与画布工具状态，主画布捕获阶段拦截原生拖拽。这样不需要一并提交此前未提交的 Image 节点改版文件。
